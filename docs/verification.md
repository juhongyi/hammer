## 실제 모델 검증

**최종 실제 모델 E2E 통과.** 사용자 API 키 설정·호출 승인 후 일반 Docker Compose 환경에서
`e2e/real-models.spec.ts`를 실행했다. 최종 실행은 약 2.2분이 걸렸다.

- Workers AI: `@cf/ibm-granite/granite-4.0-h-micro`
- Jev: `jev-1.13.0`
- 실행 기록 날짜: 2026-10-11 UTC

### 확인한 흐름

1. 한국어 요청으로 장수를 자동 결정하고, 추가·삭제·순서 변경 없이 각 페이지의 제목·핵심
   메시지·주요 내용을 웹에서 직접 편집·확정했다. 첫 생성은 6장, 다음 생성은 7장으로 결정됐다.
2. 실제 Jev가 개요 사전 판단, 문구 내용 보존 검수, 최종 문구 유형 분류, 후보 Choice 선택을
   수행했다. 요청·응답·후보 확률과 LLM 출력 스키마는 페이지별 판단 근거에 저장됐다.
3. 모든 페이지가 확정 순서대로 생성됐고 한국어 폰트와 실제 DOM 배치 검사를 통과했다.
4. 온톨로지 웹에서 목록 디자인의 용도 설명을 수정·검수하고 비교 디자인을 사용 중지했다.
   다음 생성에 새 설명이 전달되고 모든 후보에서 비교 디자인이 제외됐다. 첫 결과는 유지됐다.
   검증 후 변경한 용도·사용 여부를 복원했다.
5. 생성 문구도 직접 확인했다. 수정한 `2026년`·`12% 감소 목표`, 기존 `2시간`·개선 `30분`,
   가입·안내·지원의 세 과제, 조사→적용→확인 순서와 후속 행동이 보존됐다. 목표를 달성 결과로
   바꾸거나 개요에 없는 지원 시간·기능을 추가한 문구가 최종 결과에 포함되지 않았다.

### 실제 호출에서 발견·해결한 사항

- Workers AI는 문서의 `result.response` 외에 completion/chat-completion 응답을 반환했다.
  실제 응답 형식을 처리하고 회귀 테스트를 추가했다.
- 문구에 여러 블록이 생겨 도입용 표지의 수용 범위를 넘는 사례가 있었다. 사용자 승인으로
  Jev 개요 사전 판단과 온톨로지 기반 LLM 출력 스키마를 추가했다. 도입은 표지만 지원하도록 유지했다.
- ‘도입’과 ‘강조’의 의미가 겹친 사례는 사용자 승인한 구분 설명으로 명확히 했다.
- 목표를 검증 결과처럼 쓰거나 새 사실을 추가한 문구가 발견됐다. 사용자 승인으로 Jev 내용 보존
  검수와 새 수치 제한을 추가하고, 원문 중심의 간결한 문구 작성 지시문을 적용했다.
  실제 부적합 문구가 실패 처리되고 개요가 보존되는 것을 확인했다.

위 결과는 해당 예시에서 제품 흐름이 실제 모델로 연결되는지를 확인한 기록이다.
기존 방식 대비 품질·속도·비용 비교는 PRD의 성공 기준에 포함하지 않는다.
